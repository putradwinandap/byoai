# Mission

BYOAI's mission is to turn the AI a developer already has into part of a disciplined, repeatable, and increasingly autonomous software engineering system.

We do this by building the missing control layer around existing AI capabilities:

1. Preserve durable project context in the repository.
2. Translate human intent into bounded engineering work.
3. Supply agents with the right context and constraints.
4. Treat generated changes as untrusted until independently verified.
5. Integrate Git, CI, tests, security, review, and delivery into the workflow.
6. Convert recurring failures into permanent guardrails.
7. Measure whether autonomy, reliability, and cost actually improve over time.
8. Reuse mature external tools rather than unnecessarily rebuilding them.

## Who we initially serve

The initial audience is deliberately narrow:

- solo developers;
- indie hackers;
- students;
- freelancers;
- AI-native engineers;
- builders who already pay for one capable AI and want substantially stronger software-development workflows without purchasing an entire specialized AI factory stack.

Enterprise use is not an initial requirement. Architecture should avoid gratuitously preventing it later.

## Mission test

A proposed BYOAI feature should answer at least one of these questions:

- Does this reduce manual engineering coordination?
- Does this improve the quality of context given to AI?
- Does this increase confidence in AI-generated changes?
- Does this prevent a known failure from recurring?
- Does this make the system less dependent on a specific AI vendor?
- Does this reduce the cost or friction of autonomous development?

If not, it probably does not belong in BYOAI yet.
